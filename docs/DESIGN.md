# Дизайн и взаимодействие

## Направление
Современный, выразительный и понятный сайт ремонта. Реальные готовые интерьеры — главный визуальный материал. Украинский текст, ясная цена, удобная заявка и доверие важнее эффектов. Ранний футуристичный макет не считать утверждённым дизайном.

В чате указан структурный ориентир `https://mayster-pro.com.ua/`; это не разрешение копировать бренд, тексты или медиа. Для реализации достаточно согласованной структуры из PROJECT.md; при обращении к самому референсу сначала посмотреть его актуальное состояние.

Предложение для первой пары этапов, а не установленный фирменный стиль: тёплый светлый фон, графитовый текст, глубокий зелёный акцент в поддержку фото интерьеров; крупные снимки и спокойные отступы. Зафиксировать выбранные цвета, шрифты и размеры в едином наборе токенов. Согласовать на этапе 2, затем не менять всё оформление без причины.

- Один выразительный hero, чёткая типографическая иерархия и заметный основной CTA.
- Не более двух гарнитур с полноценной украинской кириллицей; предпочтительно одна семейство/локальные WOFF2 с нужными начертаниями.
- Ограниченная ширина контента, согласованные отступы, аккуратные карточки цен, предсказуемая навигация.
- Реальные фото не перекрывать тяжёлыми градиентами; текст на фото должен сохранять контраст. Не указывать недоказуемые преимущества.
- Основной CTA доступен на мобильном; плавающие элементы не перекрывают текст, форму, системную safe area и друг друга.

## Анимации
Допустимые источники из чата: React Bits (`https://reactbits.dev/get-started/index`), Aceternity UI (`https://ui.aceternity.com/components`), Motion (`https://motion.dev/`). Перед заимствованием конкретного компонента проверить официальную документацию, лицензию и совместимость с текущим проектом. Не устанавливать три библиотеки автоматически.

Выбрать максимум около пяти согласованных типов эффектов на весь сайт:
- Мягкое появление секций при скролле — короткое, однократное.
- Hover/focus карточек и микровзаимодействия CTA.
- Лёгкий hero parallax при достаточной производительности.
- Sticky-процесс ремонта либо компактная floating/resizable navbar.
- Плавная галерея; compare slider только с настоящими парами до/после.

Простой hover делать CSS, сложные переходы — существующей анимационной библиотекой. React Bits и Aceternity использовать выборочно как источники подходящих компонентов. Glow/gradient допустим как небольшой акцент, не как фон всего сайта. Не добавлять meteors, vortex, globe, звёзды, sci-fi, тяжёлый 3D, кастомный курсор или scroll hijacking.

Ориентир длительности: 150–300 мс для интерфейса, до 500 мс для появления. Не анимировать размеры и layout там, где хватит transform/opacity. Текст и CTA доступны сразу, без ожидания анимации. При `prefers-reduced-motion` отключать parallax и несущественное движение; на слабом мобильном устройстве упрощать эффекты. Для touch не полагаться на hover.

## Доступность и медиа
- Семантические секции, один H1, последовательные заголовки; ссылки для переходов, кнопки для действий.
- Видимый фокус, клавиатурная навигация, подписи полей и понятные ошибки, достаточный контраст. Интерактивные цели ориентировочно от 44 px.
- Галерея: Escape, корректный фокус при открытии/закрытии, осмысленные украинские alt, без блокировки клавиатуры.
- Изображения с размерами/соотношением сторон и responsive-источниками. Hero не lazy-load; нижние фото — lazy-load.
- Видео по запросу пользователя, с poster и controls; без autoplay со звуком и без тяжёлого фонового видео на мобильном.
- Проверять 360, 390, 768 и 1440 px; отсутствие горизонтальной прокрутки, обрезанного текста, конфликтов sticky-элементов и ошибок при масштабе 200%.

## Производительность и SEO
Рабочие цели, а не обещание достигнутых метрик: LCP ≤ 2,5 с, CLS ≤ 0,1, INP ≤ 200 мс при наличии реальных полевых данных. Лабораторные проверки подписывать условиями запуска; не выдавать Lighthouse за измеренный полевой INP.

Сокращать JS, шрифты и вес изображений; галерею/видео загружать по необходимости. Для greenfield React выбирать простой вариант с предварительно отрендеренным SEO-контентом; существующее приложение не мигрировать без причины.

SEO: `lang="uk"`, уникальные title/description, корректные H1–H3, реальные alt, Open Graph на основе фото клиента, canonical только на реальный домен, sitemap и robots. Разметка LocalBusiness/подходящий подтип — только с достоверными данными, без фиктивного адреса, рейтинга и отзывов. География — Ужгород и пригород, без дорвеев и повторения ключей. Preview закрыть от индексации, перед продакшеном проверить снятие ограничений. Search Console и аналитика требуют реальных реквизитов.
