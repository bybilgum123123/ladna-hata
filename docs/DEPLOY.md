# Запуск и публикация

## Локальная проверка

Требуются Node.js 24 и pnpm 11 (версии закреплены в проекте).

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Production-сервер откроется на `http://localhost:3000`. Чтобы использовать другой порт, задайте переменную `PORT` перед `pnpm start`.

## Production на Node.js-хостинге

Подойдёт хостинг, который запускает Next.js как Node.js-приложение и поддерживает оптимизацию изображений Next/Image. В панели хостинга до production-сборки задайте:

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Подтверждённый HTTPS origin без пути. Для production Vercel по умолчанию используется `https://www.ladnahata.com.ua`; переменная позволяет явно задать этот же origin. |
| `SITE_INDEXABLE` | `true` включает индексацию; на Vercel production она включена по умолчанию. Для preview оставить `false`. |

Это публичные настройки, секретов сайта в них нет. Значения `NEXT_PUBLIC_SITE_URL` и `SITE_INDEXABLE` встраиваются при сборке, поэтому после их изменения production build нужно выполнить заново. Команды хостинга:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Приложение слушает порт из `PORT`, который задаёт платформа. Не помещайте пароли, API-ключи или токены в `NEXT_PUBLIC_*` и файлы репозитория. Для проекта сейчас не требуются секретные переменные.

## Домен и HTTPS

Перед запуском владелец выбирает каноническую форму домена: с `www` или без него. В DNS и панели выбранного хостинга нужно подтвердить домен, включить HTTPS-сертификат и настроить постоянный редирект со второй формы домена и с HTTP на выбранный HTTPS origin. После этого указать тот же origin в `NEXT_PUBLIC_SITE_URL` и пересобрать приложение. Записи DNS и правила редиректа зависят от выбранного домена и хостинга; их нельзя подготовить без этих реквизитов.

## Проверка перед запуском

1. Утвердить публичное название, домен, хостинг и каноническую форму адреса.
2. Проверить получение входящих сообщений по WhatsApp и Viber на `+380988610017`; не отправлять клиенту тестовое сообщение без отдельной договорённости.
3. Подтвердить production-снимки сайта и отдельно дать команду на публикацию.
4. Собрать production с подтверждённым `NEXT_PUBLIC_SITE_URL` и `SITE_INDEXABLE=true`.
5. Проверить HTTPS, редиректы, `/`, `/robots.txt`, `/sitemap.xml`, canonical, Open Graph и JSON-LD.
6. Проверить звонок и переходы Viber/WhatsApp на реальном телефоне; убедиться, что форма готовит сообщение и не заявляет об автоматической отправке.
7. Проверить страницу на desktop и mobile после публикации. Аналитику и Search Console подключать только с подтверждёнными владельцем реквизитами.

Пока `SITE_INDEXABLE=false`, страница отдаёт `noindex, nofollow`, а sitemap не содержит адресов. Не включайте индексацию для preview-сборки.
